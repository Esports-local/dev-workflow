# 스킬 정리 기록 (2026-11-18)

esports-dev 스킬 9개 중 6개를 비활성화한다. `POLICY.md`의 자동 분류 결과가 아니라 **사람이 판단한 정리**다.

## 남기는 스킬

| 스킬 | 이유 | 기준 재현율 (baseline-sonnet) |
|---|---|---|
| `add-endpoint` | 레포 셋을 같이 고치는 절차가 있고, 누락 원인(CLAUDE.md 와 겹침) 분석의 중심 | 36% |
| `import-game` | `import_match` → `import_outputs` 순서가 정해진 명령형 작업 | 50% |
| `local-up` | 가장 자주 쓸 작업, 잘 골라지는 스킬 | 100% |

## 빼는 스킬

`add-stage`, `pipeline-run`, `translate-run`, `roi-config`, `job-debug`, `docs-sync`

## 이유

- **평가 비용**: 선택 평가 1회가 입력 약 3만 토큰이고 줄일 여지가 작다 (MCP 를 꺼도 9% 감소). 전체 평가가 108회 → 36회가 된다.
- 오선택은 0회라 스킬끼리 헷갈린 문제는 없었다. 정리 이유는 정확도가 아니라 비용이다.
- 실제 사용 기록이 아직 없어(플러그인 미설치) 사용 빈도로는 판단하지 않았다.

## 같이 바꾼 것

- 스킬 폴더 6개와 테스트 요청 파일 6개 삭제 (테스트 요청 108개 → 36개)
- 남는 스킬의 쓰면 안 되는 요청 중 정답이 빠진 스킬이던 3개는 정답을 "스킬 없음"으로: `add-endpoint-n4`, `import-game-n3`, `local-up-n3`
- 남는 스킬의 설명 · 본문에서 빠진 스킬 이름을 지움 (경계 문장은 "쓰지 않는다"로)
- 기존 결과 파일은 그대로 둔다. `run.py --report` · `classify.py` · `improve.py`는 지금 테스트 요청으로 다시 판정하므로 빠진 요청은 집계에서 빠진다
